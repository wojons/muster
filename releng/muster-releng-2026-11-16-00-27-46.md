Five tests in two packages fail on Test windows-latest. The same four pkg/daemon failures appear on every tip-era SHA measured today - 3b6ac3a3 (run 43781883786), d0116a4d (43781910075), afa9a6f7 (43782269365), 93bb13fb (43782718909) and 25bbdb3d (43782772627) - so this is deterministic, not a timing flake.

pkg/daemon guard family, four failures:
- TestStartGuard_RefusesSecondAcquire, guard_test.go:45 - "Not equal: expected: 4988, actual: 0"; the AlreadyRunningError carries no PID.
- TestStartGuard_ProbeReflectsHolder, guard_test.go:61 - the error reads "daemon already running (socket C:\\Users\\RUNNER~1\\AppData\\Local\\Temp\\ms-3045112760\\probe.sock is locked by another process)", which does not contain "daemon already running (PID ".
- TestRunningDaemonPID_ReportsGuardHolder, guard_test.go:89 - "Should be true"; running=false while a guard is held.
- TestStopRunningDaemon_RefusesToSignalSelf, guard_test.go:111 - "An error is expected but got nil"; stop returns success instead of refusing.

Root cause is structural, not timing. guard_windows.go acquireGuardLock opens the lock file with share mode 0, so the exclusive open is the lock. recordPID (pkg/daemon/guard.go:208) writes the holder PID into that same file. Both attribution readers, ownerPID (guard.go:345) and guardHolderPID (guard.go:314), try to read that file while it is held without sharing, hit ERROR_SHARING_VIOLATION, and fall back to the PID file the guard deliberately never writes (guard_test.go asserts NoFileExists). Nothing supplies a holder PID on Windows, so: AlreadyRunningError has PID 0 and its message loses the PID clause; RunningDaemonPID reports false while held; and StopRunningDaemon (guard.go:248) takes its not-running path, unlinking the pid and socket paths and returning nil. On Windows that is fail-open where Unix is fail-closed - a daemon holding the guard but not answering its socket cannot be protected from a stop that removes its paths. Unowned: zero board rows mention guard_test or TestStartGuard. Filed as RELEASE-026.

internal/builtin tenant test, one failure:
- TestTenantCommand_SeparateProcessesAgreeOnDefaultProfileFallback, tenant_cli_test.go:241 - expected "beta", actual "globex": the persisted profile wins over the fallback default in a second process. Separate product defect in cross-process default-profile resolution; filed as RELEASE-028.
