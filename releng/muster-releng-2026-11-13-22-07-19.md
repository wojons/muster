## New findings filed

### RELEASE-020 (P1) — release publisher cannot build a single artifact
`make release` (Makefile:133) loops `for main in openapi-cli openapi-daemon openapi-mcp` and runs
`go build ... -o $OUTPUT ./cmd/$main || exit 1`. At `3f5adb6`:

```
$ go build ./cmd/openapi-daemon
stat .../cmd/openapi-daemon: directory not found
$ go build ./cmd/openapi-mcp
stat .../cmd/openapi-mcp: directory not found
$ go build ./cmd/daemon          # the real path
rc=0
```

`git ls-tree 3f5adb6:cmd/` → `daemon`, `mcp-server`, `openapi-cli`. The recipe aborts on the second binary of the
first platform, leaving a partial `dist/`. `RELEASE-015` was closed on `make -n release` (dry-run never executes a
build), so the row's completion claim does not hold. `.goreleaser.yml` names the directories correctly and is the
only working publisher today.

### RELEASE-021 (P2) — zero GitHub Release objects; `RELEASE-001` closure is not reflected upstream

tags. Whatever backfill happened never reached `wojons/muster`. Combined with 730 unpublished commits since
`v0.1.1`, there is no release artifact of any kind to inventory against.
