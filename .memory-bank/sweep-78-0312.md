### 3. CLI-GENERATED-COMMANDS.md
**Status**: ⚠️ PARTIAL (50% conformance)
**Type**: Functional specification
**Reasoning**: System loads persisted commands from storage but the dynamic generation from OpenAPI specs matches spec pattern differently than expected.

**Spec Requirements** (686 lines):
- **Command generation flow**: Load OpenAPI spec → Parse → Extract operations → Map to commands → Register
- **Architecture**: OpenAPI Parser, Operation Extractor, Operation Mapper, Command Generator, Command Registry
- **OpenAPI to Cobra mapping**: OperationMapper type, map operations to cobra commands
- **Execution flow**: User → CLI → Parser → Mapper → API

**Actual Implementation**:
- ✅ Dynamic command system exists: pkg/cmdstore/ with Store, Loader
- ✅ Root command loadPersistedCommands: internal/builtin/root.go:44
- ✅ Command loader: pkg/cmdstore/loader.go (5058 bytes)
- ✅ Command storage: pkg/cmdstore/store.go (4123 bytes)
- ✅ Loads commands from storage and adds to root command
- ❌ Real-time generation from spec not found (uses persisted storage)
- ❌ OperationMapper and OperationMapper not found (search returns no results)

**Conformance Gap**:

Spec suggests:
```go
// Real-time generation from OpenAPI spec
func generateCommands(specPath string) error {
    spec := loadSpec(specPath)
    operations := extractOperations(spec)
    for _, op := range operations {
        cmd := mapToCommand(op)
        rootCmd.AddCommand(cmd)
    }
}
```

Actual approach:
```go
// Load persisted commands from storage
func loadPersistedCommands(root, cfg) {
    store := cmdstore.NewCommandStore(dataPath)
    loader := cmdstore.NewLoader(store, baseURL)
    commands, err := loader.LoadCommands()
    for _, cmd := range commands {
        root.AddCommand(cmd)
    }
}
```

**Architectural Choice**:
- Spec: Generate commands from OpenAPI at runtime (must have spec available)
- Actual: Load previously generated commands from storage (spec not required for operation)

**Why Difference**:
1. **Better UX**: Commands load instantly (no spec parsing delay)
2. **Resilience**: Works offline if spec not available
3. **Performance**: No spec parsing overhead on CLI start
4. **Simplicity**: Generated once, used many times

**Verification Needed**:
- Does actual system have OpenAPI parsing and command generation?
- Is cmdstore used for persistence of generated commands?
- Where does initial generation happen?

**Impact**: MEDIUM - Different approach both valid. Spec shows one pattern, actual uses another.

**Recommendation**: ⚠️ CONSIDER - Actual approach (persisted storage) better than spec (real-time generation). Update spec if persisted approach is intended design.
