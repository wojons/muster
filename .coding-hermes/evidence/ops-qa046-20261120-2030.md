## The defect, restated precisely (arms still UNMET at today's line numbers)

(not a git repo — host state; the 11-15 event's line numbers have shifted).

**New subfinding (this is why the row matters now):** because a detached launch exits,
`tick_pid` is dead *by design* on every run, so **any battery older than the 2h
`BUNKER_QA_ORPHAN_TTL` is unconditionally reap-eligible while still running**. The one
lock on this host proves it: created `17:59:47Z`, still `running` at `20:51:50Z`
(age 2h52m > 2h TTL, dead pid) → the next launch or collect from *any* lane will
quarantine its 549-byte partial evidence and fire an unbounded
`bunker destroy aa6c4d8b --server bunker-mvp`, killing another project's in-flight
QA run. "Dead tick_pid" is not evidence of an orphan; only agent liveness is.
