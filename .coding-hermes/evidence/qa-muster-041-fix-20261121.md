## The defect (reproduced BEFORE)

`application/x-www-form-urlencoded` request body. `pkg/openapi` read
`application/json` only, so none of those bodies produced properties; the
generated commands exposed nothing but the four generic flags and every
request went out with `Content-Length: 0` — CLI **and** MCP, silently.

## What changed

1. **`pkg/openapi/parser.go`** — body media type awareness.
   `Operation.BodyContentType` records which media type produced the body
   (`application/json` preferred, `application/x-www-form-urlencoded` fallback);
   `Operation.UnsupportedBodyType` names a declared body media type the
   generator cannot express (e.g. `application/xml`) so it can be reported
   instead of silently dropped. A schema-less form body still records the media
   type (Stripe's 273 GETs and 32 DELETEs declare `{}` there).

2. **`pkg/request/forms.go` (new) + `builder.go`** — one shared encoder:
   `FormValuesFromMap` (scalars once, slices repeated, nested maps in bracket
   notation), `ParseFormBody` (rejects empty / non-`key=value` payloads so a
   JSON blob pasted into `-b` fails loudly), `Builder.FormBody`, `Builder.RawBody`,
   and `ContentTypeFormEncoded` / `ContentTypeMultipart` constants. `Builder.Build`
   now applies the builder's media type (the MCP executors build manually and
   never call `Execute`). `Execute` also builds a multipart body when only text
   fields were supplied (no `--file`), which used to send nothing.

3. **`pkg/generator/generator.go`** — disposition: **per-property flags PLUS the
   `-b/--body` raw escape hatch** (not a refusal).
   - `-b/--body` usage now names the media type for a form op
     (`Raw application/x-www-form-urlencoded request body, e.g. 'name=Foo&email=a@b.c'`).
   - `rawBodyValue(cmd, contentType)` validates the payload against that media
     type (urlencoded vs JSON).
   - Body assembly encodes via `request.FormValuesFromMap` for form ops.
   - `isBodyMethod` keeps the body surface to POST/PUT/PATCH (Stripe's 273 GETs
     and 32 DELETEs declare empty form bodies; sending payloads there would be
     wrong).
   - Multipart ops send supplied text fields even without `--file`.
   - `reservedCLIFlagNames` + `claimSpecFlagName`: a spec property that collides
     with a CLI control flag is renamed (`header` → `--header-2`, Stripe's
     post-quotes really declares it) and the spec property name is stamped on the
     flag via `AnnotationBodyProperty`. Without this, generating the Stripe CLI
     PANICKED at startup (`flag redefined: header`) once form bodies started
     producing flags.
   - `GenerateCommands` prints a one-line stderr warning naming every operation
     whose body media type cannot be generated.

4. **`internal/builtin/generate.go`** — persistence records the media type on the
   stored command (`CommandMetadata.ContentType`) and tags body flags from the
   `AnnotationBodyProperty` stamp (falling back to the spec-derived map), so a
   collide-renamed flag still carries its real body key.

5. **`pkg/cmdstore/store.go` + `loader.go`** — the RELOADED command path (which is
   what `openapi-cli post-customers` actually runs) encodes per
   `meta.ContentType`: urlencoded, multipart (fields without a file), or JSON for
   a store written before this change (empty ⇒ JSON, backwards compatible). The
   loader also registers `--header` before the metadata loop and skips (with a
   warning) a persisted flag whose name the CLI already owns, so a legacy store
   can no longer panic the whole CLI at startup.

6. **`pkg/mcp/registry.go` + `openapi_integration.go`** — MCP parity.
   `ExecutionConfig.ContentType` carries the media type; `addBodyPropertiesToSchema`
   puts body properties (JSON, form, and multipart text fields) in the input
   schema on BOTH surfaces (`Converter.ConvertToTools` for `cmd/mcp-server`,
   `OpenAPIRegistry.ListTools`); `ToolExecutor.Execute`, `OpenAPIExecutor.Execute`
   and `ExecuteHTTPWithContentType` encode form bodies as urlencoded with
   `Content-Type: application/x-www-form-urlencoded` (multipart where declared,
   JSON by default).

## Disposition and residuals

- Form-encoded write ops: **per-property flags + `-b/--body`** (consistent for CLI
  and MCP). Multipart: **same per-property treatment** (text fields) plus the
  existing `--file` upload flag; the binary part itself is not expressible as an
  MCP argument, so MCP advertises the text fields only.
- A body declared only as a media type we cannot generate (e.g. `application/xml`)
  gets a generation-time warning naming the operation, and its command is
  argument-free by design — that is the loud path for the "unsupported type" arm.
- Schema-less form bodies on GET/DELETE (Stripe: 273 + 32) are recorded as the
  operation's media type but produce no body flags; those endpoints read query
  parameters and path params.
- `boardctl validate -C /home/kara/wojons/muster` is the foreman's step (noted,
  not run by this worker).
