## 3. Source: destroy precedes the existence check (arm 2 UNMET)

Eligibility is tick-pid death plus watchdog age only:

```
416: qa_orphan_lock_eligible() {   # <lock> <now-epoch>: dead tick and older than watchdog TTL
419:   qa_tick_pid_alive "$tick_pid" && return 1
```

`bunker list` is consulted at line 468 — *after* line 465 already issued the destroy. So a launch
against a server with zero agents still invokes `destroy` once per eligible lock; the list result
only decides whether the lock file is deleted. Arm 2 ("the launch must not invoke destroy at all")
is unmet by construction.

## 4. Source: the sweep is server-blind (arm 3 UNMET)

The loop takes `server` from the lock (line 444) and never compares it to the server the launch
is running against (`$SERVER`):

```
440:  for lock in "$dir"/*.lock; do
444:    server=$(qa_lock_value "$lock" server)
448:    qa_orphan_lock_eligible "$lock" "$now" || continue
465:    bunker destroy "$agent" --server "$server"
```

It does pass the lock's own server to `bunker`, so it does not corrupt the wrong daemon — but a
bunker-mvp launch still drives destroy traffic at agents recorded against other servers, which is
exactly the command the acceptance forbids ("a launch against server A must never issue destroy
commands for agents recorded against server B").

## 6. New sub-finding: the liveness test admits immortal locks

`qa_tick_pid_alive` is `kill -0 <pid>`, and 8 of the 16 locks record `tick_pid=7126`:

```
$ ps -o pid,ppid,lstart,cmd -p 7126
   7126       1 Mon Oct 19 15:42:26 2026 /usr/lib/systemd/systemd --user --deserialize=107
```

7126 is this user's systemd manager. A battery launched as a transient user unit records the
manager — PID 1 of the user slice — as its tick pid, so those locks are **ALIVE forever**: the
oldest (2026-11-08, 7 days) can never become eligible. Consequences: (a) the lock directory grows
without bound (16 files, 16 distinct launches, zero ever removed for this class); (b) any agent
leaked by those launches is never reaped by the watchdog — only by the ~4h agent TTL. The reaper's
death detector needs a start-time/ancestry check (e.g. compare `/proc/<pid>/stat` starttime to the
lock's `created=`), not a bare `kill -0` against a recycled-or-shared pid.
